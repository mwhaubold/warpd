# What

A modal keyboard driven interface for mouse manipulation.

## About this fork

This fork modernizes the macOS port (other platforms are unchanged):

- **Display hotplugging:** connecting, disconnecting or rearranging monitors
  and resolution changes are picked up automatically, no restart required.
- **Native look:** hints, grid, cursor and a mode indicator follow the system
  light/dark appearance and accent color (`auto`/`accent` color values,
  explicitly configured colors and fonts still take precedence).
- **Hints scale with the screen:** hints are laid out `hint_spacing` points
  apart on every display, so they are as precise on a large external monitor
  as on a laptop screen.
- **Hint wave and snapping:** hints sweep in from the pointer and the ones
  that no longer match collapse away while typing (`animations: 0` to turn
  off). A selected hint snaps the pointer onto the center of a nearby button,
  link, menu item, etc. (`hint_snap: 0` to turn off).
- **Menu bar icon:** pause/resume, reload or open the config, quit
  (`menu_bar_icon: 0` hides it).
- **Per-screen pointer memory:** screen selection returns to where the pointer
  last was on the chosen display (`screen_remember_position: 0` to always
  center it).
- **Local code signing:** builds are signed with a private identity created on
  your machine (`make signing-setup`) instead of a published key, and can be
  installed without sudo (`make install-user`).

# Installation

Make sure you have the appropriate dependencies for your system:

E.g

## debian/ubuntu:

```
git clone https://github.com/rvaiya/warpd.git
cd warpd
sudo apt-get install \
	libxi-dev \
	libxinerama-dev \
	libxft-dev \
	libxfixes-dev \
	libxtst-dev \
	libx11-dev \
	libcairo2-dev \
	libxkbcommon-dev \
	libwayland-dev &&
make && sudo make install
```

By default warpd will build a single binary for both X and wayland. An X or
Wayland only binary can be generated by setting either `DISABLE_WAYLAND` or
`DISABLE_X` at compile time.

## macos:

From source (recommended, required for the changes in this fork):

```
# Install the xcode command line tools if you
# don't already have them.
xcode-select --install

# One time: create a private code signing identity in your login keychain so
# the Accessibility permission survives rebuilds (optional, builds are signed
# ad-hoc without it).
make signing-setup

# Per-user install into ~/.local/bin (no sudo), starts warpd at login.
make && make install-user
```

Uninstallation:

```
make uninstall-user
```

(System-wide `sudo make install` / `sudo make uninstall` are still available,
`make rel` builds a universal (Apple Silicon + Intel) release tarball.)

To update: `git pull && make && make install-user`.

*Note:* On initialization you will be prompted to add warpd to your
accessibility settings; grant access to the installed binary
(`~/.local/bin/warpd`). With `make signing-setup` the permission survives
rebuilds. **When started from a terminal (e.g `warpd -f`), macOS checks the
terminal app's accessibility permission instead of warpd's own**, so run it as
the launchd service installed above rather than starting it manually.

The upstream prebuilt release can still be installed with

```
curl -L https://github.com/rvaiya/warpd/releases/download/v1.3.5/warpd-1.3.5-osx.tar.gz |  sudo tar xzvfC - / && launchctl load /Library/LaunchAgents/com.warpd.warpd.plist
```

but it does not include this fork's changes and is signed with a certificate
whose private key is public, so any program signed with it would inherit the
accessibility permission granted to warpd.

*Note 2:* Some programs (e.g iTerm) have a 'secure input mode' that may need to be
disabled in order for warpd to work properly.

warpd can be paused or quit from its menu bar icon (it is started again at
the next login). The service can be stopped/started with

```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.warpd.warpd.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.warpd.warpd.plist
```

# Quickstart

1. Run `warpd`

## Hint Mode
2. Press `A-M-x` (`alt+meta+x`) to generate a list of hints
3. Enter the key sequence associated with the desired target to warp the pointer to that location and enter normal mode.
4. Use the normal mode movement keys to select the final desination (see Normal Mode).

## Grid Mode
2. Press `A-M-g` (meta is the command key) to activate the warping process.
3. Use `u`,`i`,`j`,`k` to repeatedly navigate to different quadrants.
4. Press `m` to left click, `,` to middle click or `.` to right click.
5. See Normal Mode

## Normal Mode
2. Press `A-M-c` to activate normal mode.
3. Use the normal movement keys (default `hjkl`) to adjust the cursor.
4. Press `m` to left click, `,` to middle click or `.` to right click.
5. Press `escape` to quit.

A drag movement can be simulated from any of the above modes by focusing on the
source and then pressing the `drag_key` (default `v`) which will cause normal
mode to be activated for selection of the drag target.

A more comprehensive description can be found in the [man page](warpd.1.md) (along with a list of options).

## Wayland

*Note:* Wayland does not permit clients to globally bind hotkeys. These must be
bound within the compositor using warpd's oneshot flags.

E.g

**On sway**:

```
# warpd hotkeys

bindsym Mod4+Mod1+x exec warpd --hint
bindsym Mod4+Mod1+c exec warpd --normal
bindsym Mod4+Mod1+g exec warpd --grid
```

**Using sxhkd**:

```
# warpd hotkeys

Alt + super + x
  exec warpd --hint

Alt + super + c
  warpd --normal

Alt + super + g
  warpd --grid
```

# Limitations/Bugs

- Programs which use Xinput and or Xtest for keyboard may not work correctly
  (e.g synergy). If a specific program which you feel should be working does
  not please file an [issue](https://github.com/rvaiya/warpd/issues).

- The hack used for pointer hiding on OSX doesn't work on some programs (e.g
  iTerm). The original cursor will consequently be visible in such cases,
  though functionality should be otherwise unaffected.

- Wayland support has several limitations (see CAVEATS in the man page).
